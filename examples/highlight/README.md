# Syntax highlighting

`lmhl` highlights source text with Language Machine rules. A language is one `.lm2n` file, and the engine is unchanged: highlighting is a translation in which the output is the input with some pieces marked. It is an example of a program that embeds rulesets with `lm2n2go` and gives them a Go function to call (`../../docs/lm2n2go.md`).

| File | Contents |
| --- | --- |
| `go.lm2n`, `lm2n.lm2n` | the highlighting rules for Go and for lm2n |
| `go_lm2.go`, `lmn_lm2.go` | the same rules as Go, generated by `lm2n2go` |
| `highlight.go`, `render.go` | package `highlight`: `hl`, the spans, and the ansi, html and json output |
| `lmhl/` | the command |

## Running it

From the root of the repository:

```sh
go build -o bin/lm2l ./examples/highlight/lmhl
bin/lm2l internal/machine/engine.go         # colours for a terminal; the language comes from the extension
bin/lm2l examples/basics/calc.lm2n | less -R
bin/lm2l -format html examples/basics/calc.lm2n > calc.html
cat x.go | bin/lm2l -lang go -format json   # spans, for an editor or another program
```

Or without building: `go run ./examples/highlight/lmhl file.go`.

To run rules of your own, or these rules after you have changed them, give the file with `-rules`. A `.lm2n` file is compiled first, and a `.lm2` file is loaded as it is:

```sh
bin/lm2l -rules examples/highlight/go.lm2n file.go
```

The rules call `hl`, which only `lmhl` provides, so they do not run under plain `lm2`: `bin/lm2 -rules` prints `external not found` for each call. For the same reason `lm2n2go` on one of these files notes that the package must define `lmHl`; that function is in `highlight.go`.

After changing `go.lm2n` or `lm2n.lm2n`, write the built-in copies again and run the tests:

```sh
go generate ./examples/highlight
go test ./examples/highlight/...
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `-lang name` | from the file extension | built-in language: `go`, `lm2n` |
| `-rules file` | | highlighting rules to use instead of a built-in language |
| `-format f` | `ansi` | `ansi`, `html` or `json` |

- `ansi` writes the text with SGR colours.
- `html` writes `<pre class="hl">` with a `<span class="hl-CLASS">` for each piece, and leaves the colours to a style sheet.
- `json` writes an array of `{"start", "end", "class"}`, where the offsets are bytes in the UTF-8 source. The spans are in order and do not overlap.

With no file, or with `-`, `lmhl` reads standard input. If a file cannot be highlighted, `lmhl` reports the error and exits with status 1; in the `ansi` format it still writes the text, without colours.

## How it works

```
source ──rules (copy, and call hl)──► marked text ──highlight.parse──► spans ──► ansi / html / json
```

- **The rules copy the input and mark pieces of it.** `hl(class, text)` is a Go function that package `highlight` binds to the rules, as `lm2n2go` binds any function. It gives back the text between markers that carry the class. The rules substitute that as one symbol, and `out` writes it.
- **The positions come from the output.** The engine does not report where a symbol came from. Because the output is the input plus markers, the offset of a piece is the length of the text written before it.
- **The markers are the bytes `0xFF`, `0xFE` and `0xFD`**, which valid UTF-8 never holds, so the source cannot contain one. Input that is not valid UTF-8 is an error.
- **The output is checked against the source.** If the rules drop, add or change a character, `Spans` gives an error with the offset. A ruleset with a mistake gives an error and not wrong colours.
- **The rules cannot fail on bad source.** The last rule to be tried copies one symbol (`- out <- code - ;`), so text that no other rule understands is copied without a class. Constructs that are not closed end at the end of the line or of the input.

The classes the built-in rules use are `keyword`, `type`, `builtin`, `constant`, `function`, `variable`, `string`, `regexp`, `number`, `operator` and `comment`. A ruleset may use any class name: `html` and `json` pass it on, and `ansi` leaves a class it does not know without colour (`ansiColors` in `render.go`).

## Writing a ruleset

`go.lm2n` is the model. Its frame is:

```
 .golight()
 start var C = [ "break": "keyword", "int": "type", … ]; code <- eof ;
 eof <- code eof ;
 - out <- code - ;
```

The start rule reads the whole input as the goal `code`, so the table `C` is visible to every rule. Each other rule is filed under `code`, takes a piece of input, and substitutes it marked:

```
 .[0-9] % { repeat .[0-9a-zA-Z_.] % } toSym :N <- code - $(hl("number", N)) ;
```

Points to keep to:

- Substitute symbols (`$(N)` of a `toSym`, `"text"`, a buffer), not characters, or the rules would read the text a second time.
- A piece that needs rules of its own to find its end, such as a string, collects its text in a buffer under a goal of its own (`str` in `go.lm2n`), with rules for the new line and for `eof` that give the delimiter back.
- `%` takes the last symbol matched, so after `'//' %` the first `/` has to be added again: `format("/%s", N)`.
- Do not nest `hl` calls: the spans are flat.

To add a built-in language, add its `.lm2n` here, a `go:generate` line and an entry in `languages` in `highlight.go`, and run `go generate ./examples/highlight`. `TestUpToDate` fails when a generated file is out of date, and `TestCopiesEverything` runs each language over the sources in this repository.

## Limits

- **It is lexical.** The rules find words, numbers, strings and comments, and a function name by the bracket after it. They do not parse declarations or expressions, so there is no syntax tree and nothing like tree-sitter's queries.
- **It is not incremental.** Each call reads the whole text, at about 1 MB a second (175 KB of Go in 0.2 s). That suits files, pagers and generated pages, and an editor that highlights again on a pause, not on every key.
- **Go identifiers are ASCII.** Other letters are copied without a class, and they end a word.
- A new machine is made for each call, so `Spans` is safe for concurrent use, and loading the rules is part of every call.
